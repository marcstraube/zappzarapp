# Database Setup

## Overview

The boilerplate supports both PostgreSQL and MariaDB. Database selection is
configured via `DB_TYPE` in `.env`.

## Initial Setup

Database migrations are automatically applied during `make setup`. No manual
intervention required (zero-configuration).

## Schema Migrations

The `migrations/` directory contains SQL files for both database engines:

```text
migrations/
├── postgresql/
│   ├── 000_encryption_helpers.sql   # PGP encryption functions
│   ├── 001_users.sql                # User table with encrypted fields
│   ├── 002_audit_logs.sql           # GDPR-compliant audit logging
│   └── 003_retention_policies.sql   # Automatic data cleanup (pg_cron)
└── mariadb/
    ├── 000_encryption_helpers.sql   # AES encryption functions
    ├── 001_users.sql                # User table with encrypted fields
    ├── 002_audit_logs.sql           # GDPR-compliant audit logging
    └── 003_retention_policies.sql   # Automatic data cleanup (events)
```

## Manual Migration

After pulling updates that include new migrations, run:

```bash
make db-migrations
```

This applies all pending migrations to the configured database.

## Make Targets

| Target             | Description                    |
| ------------------ | ------------------------------ |
| `db-migrations`    | Apply schema migrations        |
| `db-cleanup`       | Run retention policy cleanup   |
| `postgres-cli`     | Open PostgreSQL CLI (psql)     |
| `postgres-dump`    | Create PostgreSQL backup       |
| `postgres-restore` | Restore PostgreSQL from backup |
| `mariadb-cli`      | Open MariaDB CLI               |
| `mariadb-dump`     | Create MariaDB backup          |
| `mariadb-restore`  | Restore MariaDB from backup    |

## Configuration

### Service Toggle

```bash
# Enable/disable database container
ENABLE_DATABASE=true    # Start postgres or mariadb container
```

### Connection Settings

```bash
# Database type: postgres or mariadb
# Determines which container starts and DSN driver (pgsql/mysql)
DB_TYPE=postgres

# Connection settings
DB_HOST=postgres    # Container name or external hostname
DB_PORT=5432        # 5432 for PostgreSQL, 3306 for MariaDB
DB_NAME=app
DB_USER=app

# Password via secrets file (recommended, auto-generated by 'make setup')
# File: secrets/db_password.txt
```

### SSL/TLS Configuration

```bash
# CA certificate for SSL connections
# - (empty):  Auto-detect internal cert for MariaDB, none for PostgreSQL
# - system:   Use system CA bundle (for cloud DBs with public CA-signed certs)
# - /path:    Custom CA certificate path
DB_SSL_CA=
```

PostgreSQL auto-negotiates SSL. MariaDB requires explicit configuration.

For PHP connections this means MariaDB needs explicit PDO SSL options — use
`DatabaseConfig::getPdoSslOptions()` when building the connection. Health checks
(`HealthCheck.php`) must use the same SSL configuration as the application,
otherwise they fail against an SSL-required server.

### PaaS/Production (Optional)

For PaaS providers (Heroku, Railway, Render), use `DATABASE_URL`:

```bash
# Takes precedence over individual variables when set
DATABASE_URL=postgresql://user:secret@localhost:5432/dbname
```

### Example Configurations

| Scenario            | ENABLE_DATABASE | DB_TYPE    | DB_HOST          |
| ------------------- | --------------- | ---------- | ---------------- |
| Internal PostgreSQL | `true`          | `postgres` | `postgres`       |
| Internal MariaDB    | `true`          | `mariadb`  | `mariadb`        |
| External PostgreSQL | `false`         | `postgres` | `db.example.com` |
| External MariaDB    | `false`         | `mariadb`  | `db.example.com` |

## Security Features

- **Encryption helpers**: Database-level encryption for PII fields
- **Audit logging**: GDPR-compliant change tracking
- **Retention policies**: Automatic cleanup of old data
- **File-based secrets**: Passwords stored in `secrets/`, not in `.env`
